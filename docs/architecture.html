Architecture of the
Living Memory.

AetherOracle is a hermetic cascade: a project-native corpus graph at the base, durable notes and transient fragments above it, and a token substrate underneath that lets every layer resonate with every query. This page documents the whole vertical.

The Mnemosyne cascade

Four strata, one memory. Each stratum feeds the token substrate; each recall blends them by resonance — content, tags, paths, scope distance and freshness.

Stufe 0 — Corpus graph

An Argonaut sounding scans every source file into corpus_nodes (files + symbols) and corpus_edges (imports / nesting / references). The graph is the project's skeleton; every node is indexed into the token substrate.

Stufe 1 — Notes

Durable, context-scoped knowledge (project_notes). Notes carry content, tags, links and a scope path; recall applies cascade resonance — the local scope outranks ancestors, siblings whisper nothing upward.

Stufe 2 — Fragments

Transient cognition with a TTL. Fresh fragments glow in recall (freshness weighting); expired ones decay and are purged lazily. The project's living change lives here: every touched file mints a corpus-delta fragment.

Stufe 3 — Token substrate

memory_tokens is the polymorphic vector base under notes, fragments and corpus nodes. Three channels — content (tf), tags (semantic anchors), paths (structure) — plus cosine similarity over the shared space.

Cartography — Arsara

Complete project mapping, woven into the cascade. The cartographer sounds the repo, remembers every file's fingerprint, and re-sounds only what actually changed. Changes glows as fragments; structure persists as map notes.

corpus_sound

Full idempotent rescan: rebuilds the graph, re-seeds the delta memory (corpus_sightings — mtime + size per file) and mints the map notes. Happens automatically on first contact.

project_sync

Incremental rite: compares the repo against the fingerprints and git status. Only added/changed files are re-sounded, deleted ones excised, imports re-wired. Catches edits invisible to fingerprints — same-size same-second edits, external tools, concurrent workers.

Auto-observe

Every create_file / patch_file / rename_file re-sights the touched path automatically (cartography.observe_edits) — the agent's own edits become memory the moment they happen. mnemosyne_observe covers edits made outside the tool loop.

Map notes

One compact overview note plus one note per project area (files, symbols, sample files, one-line description — written by the fast model when a distinct one exists, else heuristically). Tagged map, re-minted idempotently.

The flash rites — one gate, three rites

A flash turn is only worth spending when a distinct fast model exists (fast-model != model) — otherwise every rite falls back silently to the old behaviour. One runtime gate, Mnemosyne.flash_available?(rite), per-rite flags in the flash: config section.

FlashAegis

Keeps the Aegis orientation alive. post_turn_sediment (on) lets the fast model distill each turn into a summary + tags and weave them into the current Aegis — the oracle re-orients itself after every prompt without the deep mind lifting a finger. pre_turn_intent (off) would read intent before the turn.

Ouroboros

Intelligent recall (ouroboros_recall): the fast model digests the top recall hits into one current-state digest, so the deep mind navigates a distilled map instead of raw notes.

The kopist

Writes the map notes' one-line area descriptions (cartography.map-flash). Pure kartierung — never touches recall.

Concurrent workers — one shared æther

Multiple AetherOracle instances may share one project and one memory db. The cartography layer is built for this: every rite is idempotent, the db waits politely on contention, and deltas whisper across instances.

Shared delta memory

Fingerprints (corpus_sightings) live in the shared db — a worker that synced after another worker's edits sees a clean tree, never re-sounds blindly.

sync-marker fragments

Every sync with a delta mints a transient marker (worker@time: +added/changed/-removed). A sibling instance's recall surfaces "something changed over there" through normal fragment glow — no polling, no re-scanning.

Git union

git status --porcelain is unioned with the fingerprints, so content changes that mtime+size cannot see (same-size same-second edits, external tools) are still captured.

busy_timeout

The memory db waits politely (busy_timeout = 5000) instead of dying on SQLITE_BUSY when two workers write at the same moment.
