Configuration & usage

One file.
Intelligent defaults.

AetherOracle is configured through .aethercodex files — a single, hierarchical contract with sensible (slim) defaults. Every knob is optional; the oracle derives the rest.

Configuration hierarchy

Config layers merge from low to high priority normalized on load: kebab-case and camelCase both become snake_case symbols, and environment variables (AETHER_<KEY>) outrank them all. 

# merge order (low → high)
bundle config
~/.aethercodex                      # user-wide
./.aethercodex                      # walked up from the working dir
./.aether_properties                # alternate filename
# deepest wins  ·  AETHER_* env vars override everything

Models & the fast model

model is the only knob a user normally needs. Each known preset contributes its fast model, API type and endpoint automatically; a custom model sets the minimal fields directly. 

model: deepseek-chat     # known preset → everything else is derived

# --- custom model: minimal fields ---
# model:     your-model-id
# api-type:  openai        # openai | anthropic | gemini | deepseek
# api-url:   https://api.example.com/v1/chat/completions
# api-key:   sk-...        # or export AETHER_API_KEY=...

# --- distinct fast model (optional) ---
# fast-model: gpt-4o-mini  # cheaper kopist for digesting & summarizing

Known presets

deepseek-chat, deepseek-reasoner, gpt-4o, gpt-4o-mini, gpt-4.1, gpt-4.1-mini, gpt-5, gpt-5-mini, claude-sonnet-4-5, claude-opus-4-5, claude-haiku-4-5, gemini-2.5-pro, gemini-2.5-flash.

Distinct fast model

When fast-model resolves to a different identifier than model, the flash automations below are live. When they are the same, flash degrades gracefully to the old behaviour — no wasted turn.

Token scaling

Tool outputs are bounded by slim defaults so the deep mind reads only what matters. Relax any bound in a scaling: section where a bigger mirror is genuinely useful. 

scaling:
  file-overview:
    tag-cloud-limit:    12    # max tags listed per file
    file-cloud-limit:   10    # max files in the relation cloud
    notes-preview:      3     # notes shown in the overview
    note-excerpt:       200   # chars per note preview
    max-chars:          4000  # hard cap on the overview
    short-timestamps:   true  # %Y-%m-%d %H:%M, not full precision
  recall-notes:
    max-chars:          3000
    note-content:       1111
  run-command:
    max-chars:          4000

Note output is minimal by default — full created_at is shortened, scores are rounded, empty context_path and dead links are dropped. The database keeps everything; only the presentation is slim.

Flash automations

The fast model is the kopist — it digests and summarizes so the deep mind can interpret. Two rites weave it into memory automatically, and one is a recall tool. All are gated behind a single check: a distinct fast model must exist. 

flash:
  enabled:     true    # master switch for all flash rites
  intent:      false   # pre-turn intent digest (adds latency → off by default)
  sediment:    true    # post-turn Aegis weave (on by default)
  synthesize:  true    # Ouroboros note synthesis (on by default)

Flash-Aegis · intent

After a prompt is entered, the fast model distills a transient intent + focus tags into the in-memory orientation. Off by default — it adds a pre-turn round-trip.

Flash-Aegis · sediment

After the turn completes, the fast model condenses it into a new current-state summary + tags and weaves them into the persisted Aegis. The oracle flashes onto a new course on its own.

Ouroboros recall

An intelligent recall: matched notes are flash-synthesized into one compact current-state digest, so the deep mind reads a living summary instead of N stale fragments.

No distinct fast model? All four rites fall back silently manual aegis summaries) is preserved. Nothing breaks.

Cartography (Arsara)

Complete project mapping, woven into the Mnemosyne cascade. An Argonaut sounding (corpus_sound) reads the whole repository into the corpus graph (files, symbols, imports) and indexes every node into the token substrate. The cartographer then mints compact map notes (tag map) — one per project area plus an overview. Changes are read in incrementally via project_sync: only added/changed/deleted files are re-sounded, and every touched file mints a transient corpus-delta fragment — the change glows fresh in recall, then decays into the substrate (Stufe 2 of the cascade). 

# .aethercodex
cartography:
  auto-map:         true     # (re-)mint map notes after every sounding/sync
  delta-fragments:  true     # mint transient corpus-delta fragments on sync
  fragment-ttl:     3600     # half-life of the delta glow (seconds)
  map-flash:        true     # let the fast model write the map one-liners
  git-track:        true     # union with `git status` to catch fingerprint-blind edits
  observe-edits:    true     # auto re-sight files the agent writes (patch/create/rename)
  sync-marker:      true     # mint a cross-worker marker fragment on every sync

Git-assisted deltas: fingerprints see mtime + size; git sees content. sync! unions both, so same-size same-second edits and changes from concurrent workers are never missed. Edits the agent makes itself auto-observe (the write tools re-sight the touched path); the sync-marker fragment whispers the delta to sibling instances sharing the memory db.

corpus_sound

Full idempotent rescan. Rebuilds the graph, re-seeds the delta memory and re-mints the map notes.

project_sync

Incremental rite. Reads project changes into Mnemosyne: delta re-sounding + fragment cascade + map refresh. First run falls back to a full sounding.

project_map

(Re-)mint the map notes from the current corpus graph on demand. Idempotent.

Recall the map

Ask for map in recall_notes — the overview note is the landing strip; per-area notes carry file samples for targeted navigation.

No distinct fast model? The kopist stays silent — map one-liners fall back to a heuristic. Everything else (graph, deltas, fragments) needs no model at all.
